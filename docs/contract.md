# Progress contract

Stable interface of the `of1-skills` plugin. Any caller (a human, another skill, or an
automation harness) may rely on the following. Tested by `lib/contract.test.mjs`.

## Progress contract

| Contract | Detail |
|---|---|
| Status files | `$OF1_STATE_DIR/<skill>-status.json` with at least `status` (`running`, `done`, `review`, `failed`) and `skill`. One per skill: `of1-check-dependencies`, `of1-extract-design`, `of1-build-templates`, `of1-style-generative-block`, `of1-extract-brand-voice`, `of1-extract-content`, `of1-build-quick-suggestions`, `of1-build-cta-template`, `of1-publish`. `of1-build-templates` phase files (`of1-build-templates-base-status.json`, `...-intent-*-status.json`) keep a different basename so they never collide with the skill's final file. |
| Additive files | `of1-integration-result.json`. Callers must ignore file names they do not know. |
| State dir | Skills write to `$OF1_STATE_DIR` when set. Callers that poll must set it explicitly; the default (`$PWD/.of1/state`) is not part of the contract. |
| Skill ids | The 10 skill names stay stable (callers match them in dispatch text): `of1-integration` (the driver) plus the nine above. |
| Hub | `deliverables/index.html`, generated by `of1-publish`. |
| Git output | Only `of1/config/config.json` (+ `of1/config/cta-template.json` when `cta-template` is set) under `of1/config/`. |
| Non-interactive | With `non-interactive` set no skill prompts. |

## Inputs

Three arguments to `/of1-integration`; the driver exports them once as env vars so
no other skill parses arguments.

| Argument | Env var | Default | Effect |
|---|---|---|---|
| `content-source=<domain>` | `OF1_CONTENT_SOURCE` | unset | `of1-extract-brand-voice` / `of1-extract-content` crawl `https://<domain>`. Unset: crawl the site's own preview URL. |
| `non-interactive` | `OF1_NON_INTERACTIVE` | off | No skill asks questions: overwrite `/of1/brand-voice`, remove legacy `of1/config/*.json`, skip confirmation steps. |
| `cta-template` | `OF1_CTA_TEMPLATE` | off | Run `of1-build-cta-template`, commit `of1/config/cta-template.json`, enable publish check 7. |

Always required, not new: `OF1_DEMO_REPO` (absolute path to the EDS repo, derived from
the git toplevel of the cwd when unset) and a DA token (`ADOBE_IMS_TOKEN` or `OF1_TOKEN_FILE`).

`DOMAIN` (in `of1-check-dependencies`), first match wins: env `DOMAIN`, `.domain` of an
existing `$OF1_STATE_DIR/repo-config.json`, `OF1_CONTENT_SOURCE`, the production host in
`fstab.yaml`/`README.md`, then ask (interactive) or fail (non-interactive).

`of1-integration` must run from a top-level context (a subagent cannot dispatch subagents).

## Result file

`of1-integration` ends (also on failure) by writing `$OF1_STATE_DIR/of1-integration-result.json`
via `skills/of1-integration/assets/write-result.mjs`:

```json
{ "status": "done|review|failed", "summary": "...",
  "deliverables": [{ "url": "...", "label": "..." }],
  "checks": { "passed": 6, "total": 6 } }
```
